# SA-TRACKER 운영 메일 연결

회원가입 이메일 인증, 비밀번호 재설정, 비밀번호 변경 알림은 SMTP 환경변수로 발송한다. 메일 업체를 코드에 고정하지 않으며, 비밀값은 Git에 커밋하지 않는다.

## 필수 환경변수

```env
MAIL_ENABLED=true
MAIL_FROM=SA-TRACKER <no-reply@example.com>
MAIL_REPLY_TO=support@example.com
FRONTEND_BASE_URL=https://example.com
MAIL_DAILY_LIMIT=500
MAIL_TIME_ZONE=Asia/Seoul

SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_AUTH=true
SMTP_STARTTLS=true
SMTP_SSL=false
```

- `MAIL_FROM`은 메일 업체에서 확인된 발신 주소 또는 발신 도메인이어야 한다.
- 서비스 본체와 발송 평판을 분리하려면 `notify.example.com` 같은 전용 발송 하위 도메인을 권장한다.
- `FRONTEND_BASE_URL`은 사용자가 실제로 접속하는 HTTPS 주소만 사용한다.
- 587 포트는 일반적으로 STARTTLS를 사용한다.
- 465 포트를 사용하는 업체라면 `SMTP_STARTTLS=false`, `SMTP_SSL=true`로 설정한다.
- 로컬에서 실제 메일을 보내지 않을 때는 `MAIL_ENABLED=false`로 둔다.
- SA-TRACKER에서 성공적으로 발송한 메일이 한국 시간 기준 하루 500통에 도달하면 추가 발송을 차단한다.
- Gmail에서 직접 보낸 메일도 Google 한도에 포함되므로 실제 Gmail 제한은 애플리케이션 기록보다 먼저 도달할 수 있다.

## DNS 설정

메일 업체가 제공하는 값을 도메인 DNS에 등록한다.

- SPF
- DKIM
- DMARC

DNS 확인이 끝나기 전에는 발신 실패나 스팸 분류가 발생할 수 있다.

## 보안 동작

- 신규 회원은 이메일 인증을 완료해야 로그인할 수 있다.
- 기존 회원은 이메일 인증 기능 도입 후에도 로그인 상태를 유지한다.
- 이메일 인증 주소는 24시간 동안 한 번만 사용할 수 있다.
- 인증메일 재발송은 같은 계정에 60초 동안 중복 발송하지 않는다.
- API 응답과 서버 로그에는 재설정 주소와 토큰을 표시하지 않는다.
- 이메일 인증·재설정 토큰은 SHA-256 해시만 DB에 저장한다.
- 재설정 주소는 15분 동안 한 번만 사용할 수 있다.
- 같은 계정의 재설정 메일 요청은 60초 동안 중복 발송하지 않는다.
- 재설정 성공 시 기존 로그인 세션을 전부 종료한다.
- 재설정 후 자동 로그인하지 않는다.
- 비밀번호 변경 완료 알림을 별도로 발송한다.

## 운영 확인 순서

1. 새 테스트 이메일로 가입하고 인증 전 로그인이 거부되는지 확인한다.
2. 받은 인증 링크를 열고 로그인 가능한지 확인한다.
3. 인증 링크를 다시 열면 만료 안내가 표시되는지 확인한다.
4. 인증메일 재발송을 연속 요청해도 중복 발송되지 않는지 확인한다.
5. 테스트 회원 이메일로 비밀번호 재설정을 요청한다.
6. API 응답과 서버 로그에 URL 또는 토큰이 없는지 확인한다.
7. 받은 메일의 링크가 운영 HTTPS 주소인지 확인한다.
8. 서로 다른 비밀번호 두 개를 입력하면 거부되는지 확인한다.
9. 정상 변경 후 기존 로그인 세션이 만료되는지 확인한다.
10. 같은 링크를 다시 열면 만료 안내가 표시되는지 확인한다.
11. 비밀번호 변경 완료 메일이 도착하는지 확인한다.
